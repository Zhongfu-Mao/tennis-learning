# dots 接手说明

## 可以直接使用的任务说明

请把这个仓库完善为面向球友的中文网球 Wiki。优先阅读 `README.md`、`docs/WIKI_PLAN.md`、`docs/CONTENT_INDEX.md`、`docs/content-audit.json` 和 `docs/REVIEW_QUEUE.md`。

现有 181 张卡已无遗漏归入八个主栏目，13 个卡包、原文、相关词条、66 条来源记录和全部配图完整保留；12 个旧版素材文件另有逐项清单。以 `content/atlas/` 为原始编辑源，`content/wiki/` 是可复现的重组投影。不要仅凭目录名或原 `verified` 状态宣称内容都已核实。

网站定位是可浏览、搜索、互链和查证的百科。不要实现 VR 练习、个人等级路线、训练日志、SRS 复习、AI 教练设置或订场监控。`reference/progression-assistant/` 是旧 App 参考代码，不是要继续完善的产品首页。

先处理内容的通用改写与证据支持，再建立词条页面、栏目导航、术语表和搜索。保留原文 provenance、稳定 ID、关联关系和图片状态。个人经验应标注观察范围，或者经查证后重写；不要把“你”的特定弱点当成一般球友的诊断。

当前 Markdown 均 `publish: false`，catalog 均 `needs-wiki-review`。实现新的 Wiki schema 时，应建立明确的编辑状态与发布门槛，使已审稿件可以上线、草稿留在仓库供编辑核对。

## 推荐工作顺序

1. 阅读全量目录和原文；优先复核规则、健康安全以及过于绝对的技术/装备说法。给每条关键事实找能直接支持的可靠来源；保留版本/日期和适用条件。
2. 把现有短卡改成适合词条阅读的文章；保留精华，减少重复，展开需要条件解释的部分。处理来源综合判断和个人观察的边界。
3. 复核活跃配图。候选图不自动批准，`replace` 不当作最终图；同词条未被引用的旧图继续只作历史素材。内容和图上的文字/数字必须一致。
4. 选择静态内容框架，实现首页、栏目、词条、搜索、术语和来源说明。中文移动端阅读优先，每个词条有稳定分享链接。
5. 补缺以规则和技术基础、双打为先。旧 48 张知识卡与训练素材先去重、核实、改写，再导入。逐项状态由 legacy inventory 管理，避免把同 ID 的旧技术卡和 strokes 当成两篇独立词条。
6. 给大图生成适用尺寸的 WebP/AVIF 或其它衍生图，保留原始 PNG，使用懒加载。不要预缓存全部 365 MiB 图集。
7. 完成构建、内容检查、来源与链接检查、桌面/手机浏览验证之后，再配置网站部署。部署平台和网址需要在最终实现中明确。

## 当前已验证与限制

- 全部百科卡、主题、关系、图片和证据引用通过结构校验；所有 manifest 图片文件存在。
- 所有迁移源文件有 SHA-256；复制后的文件与来源快照相同。`content:check` 同时检查导出是否过时和 Markdown 本地链接。
- 原 App 在迁移前及本仓库 `reference/progression-assistant/` 按 lockfile 独立安装后，均运行 15 个测试文件、92 个测试，全部通过；TypeScript 和 Vite 构建通过。构建仍有约 796 kB 的主 JS chunk 警告。
- 本轮没有全量重新查证 181 条原文，也没有逐图重新审查；历史来源日期和图片状态原样保留。
- 当前没有完成或部署 Wiki 前端。旧 App 可运行不等于 Wiki 已实现。

## 维护命令

```bash
npm run content:generate
npm run content:check
```

生成结果不可手工单独修改。仅涉及网站投影的标题、slug、去除 VR 等调整，在 `editorial/wiki-overrides.json` 显式记录；原文仍完整保留。若要修订原文：同步更新对应来源与审核状态，再有意识地更新 `docs/source-snapshot.json` 中对应哈希（必要时改为单独的初始迁移快照加修订记录），重新生成并检查。

参考 App 的安装与验证见 README。当前 `scripts/equipment-*` 仍是旧装备审稿工具，只服务原版内容；不要拿其 62 张装备范围的通过结果代表整站审核完成。
